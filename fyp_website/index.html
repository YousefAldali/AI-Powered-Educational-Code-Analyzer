The Problem & The Idea

Why This Project Exists

Tools can show errors or even fix code, but they often do not teach the concept behind the bug.

P
The Problem
Traditional tools (compilers, linters) indicate that an error exists, but they don't explain the underlying concept. Students may rely on AI to get fixes directly, missing the opportunity to learn why the bug occurred.
S
The Idea
Combine classifier-based bug detection with a grounded tutor explanation - instead of using only one model. The classifier decides WHAT is wrong, the LLM explains WHY it is wrong.

Research Question: Can a multi-layer pipeline provide effective educational feedback for novice programmers?

1
Speed
CodeBERT classifies in milliseconds on CPU; LLMs need seconds + GPU
2
Reproducibility
Classifier gives identical output every time; LLMs are stochastic
3
No Hallucination
LLMs can invent bugs that don't exist; classifiers don't hallucinate
System Architecture

3-Layer Pipeline

Student code flows through static analysis, CodeBERT classification, and LLM-powered educational explanations.

Figure 1: End-to-end 3-layer pipeline architecture
Layer 1

Static Analysis & Baselines

Rule-based and classical ML detection methods

  • Bandit - Rule-based security scanner (Python only)
  • Keyword Matching - String match for risky constructs (eval, exec, while True)
  • TF-IDF + Logistic Regression - Classical ML baseline with GridSearch tuning
|
Layer 2

CodeBERT Bug Detection

Fine-tuned transformer classifier (125M params)

  • Model: microsoft/codebert-base, Focal Loss (γ=2.0)
  • Training: AdamW, lr=5e-6, cosine schedule, max 384 tokens
  • Split: 70/15/15 by unique ID - no data leakage
  • Threshold: Selected on validation set, frozen for test
  • Support: Rule-based fallback for common structural mistakes
|
Layer 3

LLM Educational Explainer

Qwen2.5-Coder-7B-Instruct, 4-bit quantised - not fine-tuned

  • Structured prompt enforces 5-section educational output
  • Diff injection - real unified diff injected into Section 3
  • Validation pipeline - format check + hallucinated diff detection
  • Safe fallback - template used when LLM output fails checks
Structured 5-Section Output Format
Section 1
Goal - What the code tries to do
Section 2
The Bug - Symptom, cause, misconception
Section 3
The Fix - Real diff, why it works
Section 4
Mini-Lesson - Rule of thumb, example
Section 5
Quick Check - One conceptual question

Limitations, Future Work & Conclusion

Honest Strengths & Weaknesses

L
Main Limitations
  • • Long files remained difficult (512 token limit)
  • • Subtle logic bugs still challenging
  • • LLM requires GPU for real inference
  • • Overconfident false negatives (90%+ wrong)
  • • Single-file analysis only
W
What Helped
  • • ID-based splitting fixed leakage
  • • Better data > more data
  • • Focal Loss for hard examples
  • • Code-pattern fallback support
  • • Structured prompt grounding
F
Future Work
  • • Token-level bug localisation (GNN)
  • • Longer-context models (LongCoder)
  • • Cross-file analysis
  • • Fine-tuned educational explainer
Final Takeaways
Takeaway 1
Built a full 3-layer educational code review system deployed as a web app.
Takeaway 2
CodeBERT outperformed static and classical ML baselines under strict evaluation.
Takeaway 3
Rigorous data handling was as important as model choice.
"The classifier decides what is wrong, and the LLM explains why."
